# 0.1.4 — Wake conditions: parked exclusions get a live owner

Status: **draft for review** · Target: seven-dpt-mcp 0.1.4 (stacks on the unpublished 0.1.3 `prior` commit)
Provenance: spark #27 (problem #2), from the 2026-07-27 exclusions audit — arc's calibration
ledger was found 60% ripe (12/20 resolved) with zero visibility, cached signatures had sat
unchecked at 8 since 07-12, and the `reopen` verb has never been called.

## Problem

The retire/solve convention already writes good re-open triggers (`Problem.resolution` prose,
probe-STOP notes in sparks). But a wake condition is a *wait* — "someone will re-open this
when X" — and today its owner is "a future session happening to reread the right prose."
Conditions are respected as exclusions (nothing STOPped has been improperly re-run) but
nothing evaluates them, so ripeness is invisible. Most of our conditions are volume-based
and mechanically computable from artifacts that already exist. Make the digest evaluate them.

Design stance carried over from the rest of the server: the server stores state and checks
predicates; it never decides. **No auto-reopen** — ripeness is surfaced, the model/human acts.

## Data model

Additive fields, both defaulting to `null`, backfilled in `load()` exactly like
`resolution`/`prior` were:

```ts
export interface Problem { /* … */ wakeCondition: WakeCondition | null; }
export interface Spark   { /* … */ wakeCondition: WakeCondition | null; }

export interface WakeCondition {
  summary: string;      // one-line human statement of the trigger ("corpus outgrows MVP")
  all?: WakeAtom[];     // ripe when EVERY atom is ripe
  any?: WakeAtom[];     // ripe when AT LEAST ONE atom is ripe
}                       // exactly one of all/any must be present (validated at the tool edge)

export type WakeAtom =
  | { signal: "sparkCount"; gte: number }          // total sparks in the store
  | { signal: "resolvedSparkCount"; gte: number }  // sparks with value !== null
  | { signal: "openProblemCount"; gte: number }    // for cap-drift style triggers
  | { signal: "date"; onOrAfter: string }          // "YYYY-MM-DD" — not-before gate
  | { signal: "fileLines"; path: string; gte: number }
  | { signal: "fileMatches"; path: string; pattern: string; gte: number } // lines matching a JS regex
  | { signal: "fileCount"; dir: string; suffix?: string; gte: number }    // entries in a directory
  | { signal: "manual"; note: string };            // never auto-ripens; carried for the human
```

Why these eight and no more: they cover every standing exclusion we actually have (see
Backfill), stay pure-read (no shell, no network — portability and safety), and the
count-style atoms give free **progress** readouts, which is what makes the digest useful
before anything is ripe. Paths accept a leading `~/` (expanded against `homedir()`);
anything else must be absolute. File reads are capped at 10 MB — over the cap counts as
unreadable, because the digest runs in a SessionStart hook and must stay fast.

## Semantics

- **Atom progress**: `gte` atoms report `min(current/target, 1)`; `date` is 0 or 1;
  `manual` has no numeric progress and is never automatically ripe.
- **Condition progress**: `all` → min over its numeric atoms; `any` → max.
- **Ripe**: `all` → every non-manual atom ripe AND no manual atom present; `any` → any
  atom ripe. An `all` that contains a manual atom can never auto-fire — when its numeric
  atoms are all ripe it surfaces as **"manual check due: <note>"** instead. That is
  deliberate: it encodes "date reached, now verify capture integrity by hand" without
  pretending the check is mechanical.
- **Unreadable source** (missing file/dir, oversized, invalid regex): the atom reports
  `unreadable` and the condition is surfaced **loudly and unconditionally** in the digest
  with the expanded path. A wake source that vanished must scream, not sit at 0% forever —
  the failure mode of a broken monitor is silence indistinguishable from "not ripe yet."
- **Echo the aim**: every readout prints `current/target` plus the resolved source
  (path or store counter), so a wrong aim is visible at arm time, not at wake time.
- **Nag by design**: a ripe condition appears in every digest until acted on — same stance
  as the ungraded-sparks nudge. A wait with a live owner nags; that is the feature.

Lifecycle rules (predictable over clever):

- `update_problem status: "open"` (reopen) auto-clears `wakeCondition` — parked → active.
- `update_spark` reaching terminal status (`worked`/`failed`) auto-clears it — resolution
  unparks. Everything else is explicit: pass `wakeCondition: null` to clear, an object to
  set/re-aim, omit to leave untouched.

## Tool surface

1. **`update_problem`** gains optional `wakeCondition` (nullable). Description gains:
   "…for a retirement, prefer a structured wakeCondition the ambient digest evaluates —
   the re-open trigger becomes a checked condition, not a remembered one. Keep the prose
   `resolution` for the WHY."
2. **`update_spark`** gains the same optional nullable param (park a HOLD/STOPped probe
   spark with its re-run trigger).
3. **`capture_spark`** gains it too — a spark born gated on a future condition (spark #22's
   shape) declares the gate at capture.
4. **New read-only tool `wake_status`**: no required input, returns the full ledger — every
   problem/spark carrying a condition, with per-atom `current/target` echoes, progress,
   and state (`ripe` / `ripening` / `manual-gate` / `unreadable`). This is the on-demand
   view for curation passes; the digest stays compact.
5. **CLI parity**: `--digest` includes the wake section (below); a new `--wake` flag prints
   the full ledger for ops use (timers, cron) without starting the server.

Zod: `z.discriminatedUnion("signal", …)` for atoms; `.refine` for exactly-one-of `all`/`any`
and non-empty atom arrays; invalid conditions are rejected loudly (`isError: true`), never
stored half-checked.

`fmtProblem`/`get_problem` formatting: closed entries with a condition append one line —
`wake: 40% (signatures 8/20)`.

## Digest format

Appended to the existing blocks, in this order:

```
[seven-dpt] WAKE — ripe, act or re-park:
  spark #22 — arc prior-ledger reaches ~20 resolved probes · fileMatches 21/20 ✓
    → act on its nextStep, or re-aim with update_spark(22, wakeCondition: …)

[seven-dpt] wake source unreadable — fix the aim:
  problem #5 · fileCount ~/…/signatures → ENOENT (dir moved?)

[seven-dpt] ripening: spark #22 12/20 (60%) · #5 sigs 8/20 (40%) · #25/#26/#28 gate 2026-08-11
```

Rules: RIPE and UNREADABLE sections always shown when non-empty. The `ripening` line is a
single compact line, top 3 by progress; omitted entirely when nothing is parked. Silence
stays the default (`buildDigest` already prints nothing rather than noise).

## Store changes

- Both interfaces gain the field; `load()` backfills `wakeCondition: x.wakeCondition ?? null`.
- `save()` unchanged (JSON round-trips the object).
- New `evaluateWake(cond, db): WakeReadout` and `wakeLedger(): WakeEntry[]` in `store.ts`;
  all formatting stays in `index.ts`. Evaluation is synchronous fs reads under try/catch;
  no caching (n≈10 conditions, files are small).

## Verification

Unit (`node --test`, zero new deps; fixture store via the existing `SEVEN_DPT_DB` override
plus a tmp dir):
- progress math for each atom kind; `all`=min / `any`=max; date boundary
- manual gating: `all` with manual → never ripe, reports `manual-gate` when numerics ripe
- unreadable: missing path, >10 MB file, invalid regex → `unreadable`, never a throw
- lifecycle: reopen clears; terminal spark status clears; `wakeCondition: null` clears;
  omitted leaves untouched; malformed condition rejected at the tool edge
- digest: ripe renders, single ripening line caps at 3, silence when nothing parked

Live acceptance (after backfill, against the real store):
1. `--digest` shows `spark #22 12/20 (60%)` and `#5 sigs 8/20 (40%)` on the ripening line.
2. `wake_status` echoes match the ground-truth table above, all sources readable.
3. **Force a known hit**: temporarily set spark #22's `gte` to 12 → RIPE block appears with
   the act/re-park pointer → restore to 20. Never trust a detector whose silence you
   haven't distinguished from blindness.
4. Simulated unreadable: point a scratch condition at a nonexistent path → the unreadable
   block appears (then remove it).

## Non-goals / future

- **No auto-reopen, no auto-anything** — surfacing only. Graduation to any automatic action
  goes through the read→draft→act ladder (spark #2) like everything else.
- **No shell/exec or network signals** — file + store-counter reads only, so the npm package
  stays portable and inert. User-specific paths live in user data (the backfill), never in code.
- **Evaluation is session-gated**: the owner is "next `--digest` run." If no sessions run,
  nothing evaluates — acceptable because acting also requires a session; `--wake` exists if
  a timer ever wants to watch independently.
- **`lte`/negative atoms** (e.g. "EMPTY-SLICE count == 0" as a computable integrity check):
  deferred until a second real predicate needs them; today's single case is a manual note.
- **Spark #14 unification**: the expiry sweep (auto-propose retire when scope lapses) is the
  same evaluator run in reverse; the atom vocabulary was chosen to be reusable for it. Not
  in 0.1.4.
